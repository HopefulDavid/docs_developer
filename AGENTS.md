# Developer documentation site

Czech how-to articles for developers, published as a DocFX site to GitHub Pages. People read the Czech `README.md`.

## Articles

- Articles in `content/` are the published product. Write them in neutral Czech under the shared language rules, with no second-person address and no imperatives, and give headings a descriptive form (`Výběr typu zálohy`, not `Vyber typ zálohy`), because the owner decided against addressing the reader. `tests/style.test.js` catches common second-person forms, while singular imperatives (`ověř`, `nastav`) need your own review.
- Teaching third-party tools is the purpose of the articles, so their installation, configuration and troubleshooting belong in the articles. The shared rule that keeps third-party setup out of project documentation applies only to `README.md`.
- Every article starts with `description` front matter and has an entry in its area's `toc.yml`. `content/toc.yml` groups areas into navbar menus (an entry with `items`), and `scripts/content.js` treats every entry with an `href` folder as an area, so add a new area inside a group rather than as a fourteenth top-level item. Overviews between the `přehled` markers are generated by `bun run build:overviews`, so never edit them by hand.
- A moved article leaves a redirect file (`redirect_url` front matter) at the old path, because published links must keep working.
- Put each sentence of running text in its own paragraph, because every article follows this layout.

## Commits

- Commit messages appear on the public changelog page. Put generics, placeholders and tags such as `<T>` in backticks and leave out links and images, because the subject is rendered as Markdown and a broken relative link fails the build.
- After each commit and before a push, run `bun run build` (about 10 s, rewrites the ignored `_site` and `content/changelog.md`, and stale overviews). When it warns about `changelog.md`, amend the unpushed commit, because a pushed message stays on the page.
- A push to `main` publishes the site after CI passes, so push only with the owner's approval.

## Validation

Run from the repository root in PowerShell. Setup: `bun ci` and `dotnet tool restore`.

- `bun run validate`: overview check (`check:*`), tests and the full build (`build:*`, a DocFX build with warnings as errors). Run it before every commit. CI runs the same script.
- After changing `templates/material` or the DocFX version, also run `bun run preview` (long-running, port 4173) and check the browser console, light and dark theme, a narrow window, search and the outline, because `validate` passes with broken JavaScript or CSS.
